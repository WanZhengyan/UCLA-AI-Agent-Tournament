# PokemonChampion — Linux 宝可梦参赛程序

## 当前本机版本：宝可梦 + 红警

2026-10-15 本机 Python 源码已升级为双游戏版本。仍使用此文件夹和原来的虚拟环境：

```bash
.venv/bin/python exe_entry.py
```

一个监听进程、一份 Official Agent Key，自动接宝可梦 VGC 双打选秀和红警 Red Alert 的测试赛与正式比赛；每个席位由官方 SDK 启动独立工作进程。狼人杀等其他游戏保持忽略。
请不要同时启动下载包中的独立红警程序或另一个相同密钥实例。

红警策略最初来自下载目录的 `RedAlertChampion.zip`，现已更新为攻守经济平衡版：双矿起步、补电补矿车、少量守军护家、优先打暴露目标；发现炮塔封锁后停止硬冲，前排留在估计射程外，炮兵单独攻击。记住已侦察到的炮塔位置，近期明显亏损时整队；补攻城科技时保留运营资金并预估电力需求。红警使用实时订单批次，订单回执由同一局的红警策略处理。宝可梦策略文件未改动。
统一的 `--self-test` 会检查两种策略和子进程启动；`--check` 仅检查连接，不接赛。保持电脑联网且不要合盖。

红警测试赛：平台 Testing 页面选择 Red Alert，自己的席位选 Mine (self-hosted)，等待对手连接。正式比赛仍需在平台完成对应赛事报名；程序不会代替报名。

2026-10-15 红警默认现为 `eco_guard` 的 `armor_guard_v4`：在地图适配基础上采用坦克主力、有限步兵支援，并收紧不利交战检查。下一场新接入的测试赛和正式赛均使用它；已开始的比赛不热切换。自动新旧版对照暂时关闭，因此两个 Mine 席位也都使用最新版。不是已证明最优的策略；宝可梦不变。

### 坦克主力修订（armor_guard_v4）

- 先保电力与采矿，尽早补维修厂解锁中/重型坦克；不再优先堆到多座兵营。经济成熟后第二战车工厂优先于额外兵营。
- 给坦克留启动与生产资金，利用平台逐步扣款机制；辅助步兵数量受限，避免每笔小额收入都被步兵吃掉。敌坦克出现时补少量火箭兵、优先适用的反坦克防御；不会为造特斯拉直接拖垮电力。
- 进攻队需有至少三辆半血以上坦克；贫血坦克、留守坦克不充当实际进攻主力。步兵对坦克的估算权重降低，逆风或最后几十秒也不能跳过明显不利的交战检查。己方经济被袭仍优先处理，不是永远不进攻。
- 扩矿需有装甲护卫；发现炮塔仍保留原有避让及有条件的炮兵支援。所有数量、预算和对阵系数都是启发式阈值，不是引擎战斗模拟或学得的最优参数。
- 304 项回归检查与双游戏/工作进程自检通过。固定收入、无战斗的 10 分钟生产模拟：低收入旧版两阵营均为 31 步兵/0 坦克，新版盟军 15 步兵/4 坦克、苏军 15 步兵/3 坦克；两版矿车数量相同。此结果验证预算方向，不证明线上胜率提高。

公开仓库包括双游戏策略、统一 agent、官方运行组件、本地监控、自测框架和测试。密钥、环境文件、私有比赛日志、历史备份与未重建的 Linux 二进制不上传；下文引用的部分历史 validation 产物只保留在原本机目录。

双游戏接入时 135 项离线检查通过；红警攻守平衡更新后 159 项通过。三组相同输入的新旧决策对照确认：旧版整队冲塔，新版前排保持距离、炮兵单独开火。测试包含简化生产场景，不是真实 OpenRA 对战，不能证明新策略胜率提升。攻守更新报告见 `validation/redalert_balance_20261015.json`，原接入报告见 `validation/dual_game_20261015.json`。
更新不重启监听器、不打断当前比赛；新比赛工作进程自动载入新版，已经进行中的比赛继续使用其已加载版本。路径风险检查使用近似直线路径，不是完整引擎寻路或伤害模拟。
下面的独立 Linux 可执行文件说明属于原发行版；该二进制未重新打包，不包含本次双游戏更新。

### 双游戏自动记录与失败复盘（2026-10-15）

新启动的宝可梦、红警测试赛和正式赛工作进程默认启用被动记录。红警约每 5 秒游戏时间保存己方经济、军队位置、可见敌人、地图适配方案、拟提交订单和回执计数；宝可梦保存逐次公开场面、拟提交动作和耗时。每场终局结果独立保存，失败局自动进入复盘清单。缺电、矿车归零、净交换亏损、反复订单问题只是排查提示，不直接断言失败原因。

记录目录：`validation/match_monitor/`。每个席位独立的 `*-latest.json` 为最近观测，`*-final.json` 为终局，`.jsonl` 为时间线（每席位最多 8 MiB；不自动删除历史文件，请定期归档）。文件权限 0600，不保存密钥、原始上下文或隐藏对手信息。不抓取旁观者信息，不与另一个席位共享战况，不改变策略。

```bash
.venv/bin/python -m match_monitor
```

此命令只读汇总已有记录；`review_queue` 列出确认失败、认输或超时的结果文件。记录陈旧/没有终局不能推断失败，也不能证明程序已断线。`pending` 不代表订单最终成功；周期采样和受限订单缓冲不等同于完整引擎回放。只有终局原始观测本身标记 terminal 才声明精确终局观测。

自动记录随现有比赛程序运行，无需启动第二个接赛器。部署前已开始的比赛不热插入、不重启，无法补回当时未记录的过程；网站历史回放仍需能访问的链接或导出。不会在聊天结束后自动进行模型逐局分析或推送消息。`COMPETITION_MONITOR_DISABLED=1` 或 `POKEMON_BOT_NO_CACHE=1` 可禁用新记录；离线测试默认不记录。仅本机源码部署，Linux 可执行文件未重建。

### 红警自我对战对照框架（当前已关闭）

`validation/redalert_selfplay/settings.json` 控制对照实验，当前 enabled 为 false，所有新红警对局均使用部署默认版。将来重新启用时，仅当官方 assignments 确认同一 Testing 红警对局的两个座位都属于本账号才运行 `balanced`（旧基线）与 `eco_guard`（防守经济地图版）的对照；其他比赛仍用部署默认版。防守经济版以保护经济圈为主，安全机会或末段交换分落后时再进攻；扩矿使用本局剩余时间、运行时建造时长、保守行军估计和收益窗口，替代固定开局秒数。这个窗口不是实测回本时间。

同一地图、同一时长的相邻两场自动互换策略座位；三张地图建议先做 10 分钟小样本，再复测 15/20 分钟。阵营与随机种子由平台决定，互换座位并不能消除全部随机因素。两个策略进程不读取对方的战况文件。

每 5 秒记录己方经济、交换分、兵力数量、策略模式、首次双矿/四矿车/第二基地时间及订单统计。仅记录字段白名单，不记录密钥和完整原始上下文；结果在对局结束后单独写入。`harvester_disappearances` 是采样中矿车消失次数，不保证全部都是被击毁；没有最终 observation 时明确标记末次采样，不冒充精确终局资产。即时 `pending` 回执也不视为引擎最终接受。

第一轮日志保留在 `validation/redalert_selfplay/eco_guard_v1/`。实战发现共用执行器会对已生产完成的步兵/车辆错误发送 `place`；下一轮 `eco_guard_v2` 修复此问题，只有 Building/Defense 队列物品能放置，同时补充矿车位置与去重后的引擎最终回执记录。v2 对双方应用相同修复，先让候选版坐 1 号位。跨版本两场不算严格互换对照，汇总单独计数同源码版本的完整互换组。

v1 终局写出失败，该场两方胜负从官方运行器控制台恢复，结果文件明确标记 `supervisor_console_recovered`；最后周期采样不冒充精确终局观测。v2 将权威结果保存与终局观测解析分离，并且两处结果输出分别容错。候选版也取消最后 75 秒全军后撤，保持经济圈防守；这是针对 v1 最后一分钟矿车大量消失提出的待复测修正，并不证明全部矿损都由后撤造成。

v2 历史日志（若有）位于 `validation/redalert_selfplay/eco_guard_v2/`。汇总命令：

```bash
.venv/bin/python -m redalert_bot.selfplay
```

只有两个席位都有终局结果、策略不同、源码版本一致的对局才计入比较；进行中或记录不完整的局不算胜负证据。关闭 settings 的 enabled 只影响下一场新启动的实验，不中途切换策略。SDK 本地扩展记录于 `SDK_PROVENANCE.txt`。

### 地图适配基础（2026-10-15，map_guard_v3；当前由 v4 继承）

用户已要求直接用于比赛，故 `eco_guard` 成为红警部署默认版，自动对照关闭；保留 `balanced` 供以后显式实验。不把尚未完成真实地图对照的版本称为最优策略。已开始的比赛不热切换；宝可梦文件未修改。

- 读取本局地图编号、公共出生点、初始矿区和地形，缓存保守的地面连通图。不是按地图名硬编码胜者；实时配置优先。
- 接敌路线较短时，保留更多早期步兵、更早考虑一座护矿防御，限制扩矿距离并提高扩矿护卫门槛。出生距离至少 70 格或保守网格路径至少 90 步、且附近有初始资源时，候选版减少早期步兵开支、允许较远扩矿。阈值是待验证的规则，不是训练所得最优值。
- 扩矿时用可达路径长度估算行军耗时，结合剩余时间与实时建造时长判断；已缓存的矿点遇到新炮塔或附近敌人会重新检查。初始矿区数量不代表当前剩余矿量，路径也不是引擎真实寻路或精确回本模型。
- 防守模式增加一名步兵的前置预警侦察，危险时撤回，一局最多尝试两次，避免不断补兵送侦察。主力继续护矿；已知炮塔风险和本地入侵优先于地图开局参数。
- 缺地形/出生点或敌我不连通时采用保守回退，不凭镜像猜测开启经济型开局。计时字段缺少 remaining_seconds 时，改用本局 max_minutes，不再一律按 20 分钟推算。
- 自测日志新增 map_plan，记录实际选择与依据。新日志位于 `validation/redalert_selfplay/map_guard_v3/`，不与 v1/v2 混为同版本换边证据。新增检查使用合成地形，尚无 v3 真实地图胜率数据。

适用：AltruAgent `pokemon_vgc_doubles_draft`。这是 Linux 原生 ELF 程序，不是 Windows EXE。

## 最快启动

下载 `PokemonChampion-linux-x86_64` 后，在下载目录执行：

```bash
chmod +x PokemonChampion-linux-x86_64
./PokemonChampion-linux-x86_64
```

按提示粘贴比赛平台的 **Official Agent Key**（`eak_live_...` 开头），按回车。输入时不显示字符，这是正常的。
这里只需要平台密钥，不需要 OpenAI 或其他模型 API key；全部策略本地计算。

程序默认同时接你的宝可梦测试赛和正式比赛，保持终端和网络连接。它会等待平台分配对局，自动选秀、选队和战斗。
平台端需已完成报名，在 Agent Configuration 选择 Self-hosted；正式赛事还需在页面注册参赛。
测试赛在 Testing 页面创建，自己的席位选 Mine (self-hosted)。运行程序本身不会替你创建或注册比赛。

## 系统要求

- Linux x86_64 / amd64，glibc 2.35 或更新，例如 Ubuntu 22.04+、Debian 12+。
- 不支持 ARM64，也不支持仅有 musl 的 Alpine。不同架构可使用附带源码运行或在目标系统重新打包。
- 可联网到比赛平台；不需要安装 Python、Node、CUDA，也不需要 GPU。
- 可用的可执行临时目录。若系统将 `/tmp` 挂载为 `noexec`，设置 `TMPDIR` 为你可写且允许执行的目录后启动。
- 只运行一个同密钥实例；Ctrl+C 停止程序，不主动认输。停机仍可能触发平台计时或缺席判负。

## 常用命令

```bash
./PokemonChampion-linux-x86_64 --self-test     # 离线自检，不用密钥
./PokemonChampion-linux-x86_64 --check         # 输入密钥后，仅检查连接，不接赛
./PokemonChampion-linux-x86_64 --match         # 只接测试赛
./PokemonChampion-linux-x86_64 --tournament    # 只接正式比赛
```

非交互环境可以设置 `ALTRUAGENT_OFFICIAL_AGENT_KEY`，或用 `--key-file /path/to/key.txt`。
密钥文件只放密钥本身；建议 `chmod 600 /path/to/key.txt`。也可参考源码内 `.env.example`。
交互输入的密钥不保存到磁盘；不要把密钥当作命令行参数。程序会缓存同局公开选秀配置，便于重启后继续使用已知信息；缓存不包含密钥。

## 策略

- 选秀：固定配置的能力、道具、招式、配合、覆盖与对手补强需求；有限蛇形顺序预测。
- 选队：六选四、首发组合和后排换入价值，兼顾平均对局和较差对局。
- 战斗（当前 Mac 源码）：联合比较两个位置的合法动作，预测对手多种回应，按加权平均局面收益选择，保留下一回合局势估值；不再叠加最差尾部和最坏情况惩罚。
- 建模：常见属性与特性、速度与优先度、保护成功率、击掌奇袭、顺风/空间、天气场地、引导、换人及友伤。
- 稳定性：直接使用官方 SDK 的认证、MCP、租约、重连、多进程；输出前检查当前合法模板；异常时使用合法回退。

搜索采用近似伤害与状态模拟，并裁剪行动空间；没有完整随机事件树，也没有训练后的胜率模型或完整两回合极小极大搜索。
不读取隐藏指令或未公开的对手配置。断线恢复缺少完整配招时，使用公开图鉴先验估计威胁。
平台没有太晶动作，程序不会提交太晶请求。

## 源码运行与重建

源码包包含完整策略、图鉴、官方 SDK、测试和说明。Python 3.11+：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python exe_entry.py --self-test
.venv/bin/python exe_entry.py
```

`bash build.sh` 会在当前 Linux 环境构建本机可执行程序。新二进制的架构与最低系统依赖取决于构建环境。

本项目回归测试：安装 `pytest`，运行 `python -m pytest tests -q`。
独立 Showdown 基准：在源码目录执行 `npm install` 安装固定版本的测试引擎，然后用已安装运行依赖的 Python：

```bash
PYTHON=.venv/bin/python node tests/showdown_benchmark.js 12 100
```

或将 `BOT_EXEC` 设为最终二进制的绝对路径进行可执行文件测评。基准的结果只用于发现错误和记录离线表现。

新旧源码直接对打（每份源码需包含 `tests/bridge.py`；结果目录须尚不存在；局数为 4 的倍数）：

```bash
PYTHON="$(pwd)/.venv/bin/python" A_DIR=/absolute/new-source B_DIR=/absolute/old-source RESULT_DIR=/absolute/new-results node tests/showdown_compare.js 24 2000
```

测试会交换阵容归属和玩家席位，隔离每局记忆，并拒绝非法动作和策略回退。四种手工阵容的结果不代表正式赛事或选秀表现。

官方协议来源与 SDK 版本见 `SDK_PROVENANCE.txt`；图鉴许可和来源见 `licenses/`。
